# 05. 파일별 코드 설명

저장소의 모든 파일을 하나씩 설명합니다. (라인 수는 2026-07 기준)

## app.py — 웹 버전 Flask 서버 (601줄) ✅ 메인

웹 버전의 백엔드 전부. 크게 4부분으로 나뉩니다.

### (1) 전역 상태와 유틸 (1~62행)

- `log_queue`: 모든 로그가 모이는 전역 큐. SSE로 브라우저에 흘려보냄
- `is_running`, `scheduler_thread`: 스케줄러 실행 상태
- 경로 상수: `CONFIG_FILE`(config.json), `QUEUE_FILE`(queue.json), `SESSION_DIR`(sessions/)
- `add_log(message)`: 타임스탬프 붙여 큐에 넣고 터미널에도 출력
- `load_config/save_config`, `load_queue/save_queue`: JSON 파일 읽기/쓰기 (파일이 없으면 기본값 반환)

### (2) REST API 라우트 (64~392행)

| 함수 | 경로 | 하는 일 |
|------|------|---------|
| `index` | `GET /` | index.html 렌더 |
| `handle_config` | `GET/POST /api/config` | 설정 저장/조회 |
| `handle_accounts` | `GET/POST/DELETE /api/accounts` | 계정 추가/삭제/목록. GET은 `sessions/<safe명>.json` 존재 여부로 "로그인 완료/필요" 상태를 만들어 반환 |
| `rename_account` | `POST /api/accounts/rename` | 닉네임 변경. config의 accounts와 account_handles, 세션 파일명, queue.json의 account 값까지 한꺼번에 갱신 |
| `api_ai_rewrite` | `POST /api/ai/rewrite` | 표의 🔄 버튼용. `rewrite_content()` 호출해 리라이팅 결과 반환 |
| `handle_login` | `POST /api/login` | `ThreadsProUploader.run_manual_login()`을 **별도 스레드 + 새 이벤트 루프**에서 실행 (Flask 요청은 즉시 응답하고 브라우저 창은 뒤에서 뜸) |
| `upload_file` | `POST /api/upload_file` | CSV/엑셀을 pandas로 읽어 행 배열(JSON)로 변환. 헤더 문자열에 "내용/댓글/파일/태그/주제/시간/언어/ai/계정" 키워드가 포함되면 해당 열로 자동 매핑, 못 찾으면 열 순서 기반 추측. **내용이 빈 행은 직전 행의 댓글 연장으로 병합**하는 로직 있음 |
| `handle_queue` | `GET/POST /api/queue` | 대기열 조회 / 전체 교체 저장 |
| `stream_logs` | `GET /api/logs` | SSE 스트림. 5초간 로그가 없으면 keep-alive 주석 전송 |
| `handle_start/stop/status` | `/api/start,stop,status` | 스케줄러 제어 |

### (3) 스케줄러 `scheduler_loop()` (398~568행) — 핵심

5초마다 도는 무한 루프. 동작:

1. 현재 시각 `HH:MM` 문자열을 만들고, 직전에 처리한 분(`last_checked_minute`)과 다르면 대기열 검사
2. `status == "Pending"`이고 `time == 현재시각`인 행을 찾으면:
   - `running_accounts` 집합으로 같은 계정 중복 실행 방지 (실행 중이면 건너뜀)
   - 상태를 `Running`으로 저장
   - **미디어 경로 전처리**: 쉼표 분리 → `Desktop/thread_ing` 경로 치환 → NFC/NFD 유니코드 보정 → 폴더면 내부 파일 나열 (행 번호 접두사 `N_` 하위폴더 우선 탐색)
   - **AI 리라이팅** → **태그/주제 본문 병합**
   - `run_upload_task`를 **새 스레드**로 실행: 새 이벤트 루프에서 `post_to_threads()` 호출, 결과에 따라 상태를 `Success/Fail`로 저장하고 `running_accounts`에서 제거
3. 처리한 행이 있으면 `last_checked_minute`를 갱신해 같은 분에 중복 발사 방지

⚠️ 이 함수에는 "같은 계정 작업이 밀리면 그 분이 지나간 뒤 영영 실행 안 됨", "queue.json 덮어쓰기 경쟁" 등 알려진 문제가 있습니다 (문서 06).

### (4) 서버 기동 (598~600행)

`app.run(host="127.0.0.1", port=5001, debug=True, use_reloader=False)` — 로컬 전용, 디버그 모드 켜짐(리로더는 꺼서 스케줄러 스레드 중복 방지).

## uploader.py — 자동화 엔진 (1147줄) ✅ 핵심

### `rewrite_content(text, provider, api_key, system_prompt)` (13~69행)

AI 본문 리라이팅 함수. `provider`가 `GPT`면 OpenAI `gpt-4o-mini`(max_tokens 400, temperature 0.7), `Gemini`면 `gemini-2.5-flash` → `gemini-2.0-flash` → `gemini-flash-latest` 순서로 성공할 때까지 시도. **어떤 에러가 나든 원문을 그대로 반환** (리라이팅 실패가 게시 실패로 이어지지 않게 설계됨 — 대신 조용히 원문이 올라감).

### `ThreadsProUploader` 클래스 (71~853행) — 웹 버전이 쓰는 엔진

| 메서드 | 하는 일 |
|--------|---------|
| `human_move_and_click(page, target)` (82행) | 봇 감지 회피용 클릭. 마우스 좌표를 **3차 베지에 곡선**을 따라 15~25 프레임으로 나눠 이동시키고, 타겟 정중앙이 아닌 ±10% 오차 지점을 클릭 |
| `human_scroll(page, delta_y)` (128행) | 휠 스크롤을 8~15단계로 나눠 ease-in-out 가감속으로 굴림 |
| `click_element(page, selector, ...)` (156행) | 4단계 폴백 클릭: ① 사람형 클릭 → ② 일반 클릭 → ③ force 클릭 → ④ JS `el.click()`. 아이콘(svg)이 걸리면 조상 버튼 요소를 찾아 클릭 |
| `run_manual_login(username)` (220행) | **수동 로그인 창 관리.** `profile_<계정>` persistent 크롬을 headful로 띄움 → 인스타그램 로그인 페이지로 이동 → 사용자가 직접 로그인 → 인스타 쿠키(`sessionid`) 감지 시 threads.net/login으로 자동 이동 → 404 화면이면 홈으로 자가 복구 → 로그인 완료 요소(홈/프로필 아이콘 등) 감지 시 `storage_state`를 `sessions/<계정>.json`에 저장. 실제 로그인된 핸들(@아이디)을 추출해 config.json의 `account_handles`에 기록. 비정상 종료로 남은 크롬 `SingletonLock` 파일도 정리 |
| `post_to_threads(username, headless, content, media_paths, comment_text, topic_text, publish_delay)` (371행) | **게시 본체.** 문서 04의 "게시물 하나가 올라가기까지" 4번 단계 전체. 요약: 세션 주입 → 로그인 검증 → 피드 워밍업 → 작성 모달 열기(버튼 클릭, 실패 시 단축키 `c`) → 본문 타이핑 → 미디어 첨부(input 직접 주입 → FileChooser 폴백, img 개수로 업로드 완료 폴링) → 댓글 있으면 "스레드에 추가" 후 두 번째 칸에 타이핑, 링크 미리보기 카드 제거 → 게시 버튼 활성화 대기 후 클릭(3회 재시도) → "취소" 버튼이 사라졌는지로 성공 판정 → 실패 시 스크린샷 저장. 게시 순간의 POST 네트워크 요청/응답을 로그로 남기는 리스너도 등록 |

주의할 점:
- 선택자가 한국어/영어 UI 라벨(`"게시"`, `"Post"`, `aria-label="새로운 스레드"` 등)에 하드코딩되어 있어 **Threads UI 개편이나 언어 설정에 따라 깨질 수 있음**
- `topic_text`와 `publish_delay` 파라미터는 받기만 하고 **본문 안에서 사용되지 않음** (topic은 app.py가 해시태그로 본문에 병합하는 방식으로 대체됨)
- headless일 때와 headful일 때 viewport와 user-agent 설정이 다름

### `ThreadsUploader` 클래스 (855~1147행) — 구버전 GUI(main.py) 전용

- `get_upload_folders()`: 작업 폴더에서 `[완료]`가 안 붙고 숫자로 시작하는 폴더를 번호순 정렬해 반환
- `parse_folder_contents(folder)`: 폴더 안의 미디어(jpg/jpeg/png/webp/mp4/mov, 파일명 숫자순)와 `.txt` 본문을 파싱. txt가 없으면 폴더명(숫자 접두사 제거)을 본문으로 사용
- `load_excel_data(path)`: 엑셀/CSV를 읽어 `폴더명/본문/댓글` 열을 이름으로 매핑 (실패 시 1·2번째 열 사용)
- `start_upload_process(excel_path, delay_minutes, is_headless)`: 엑셀 행 순회 → 폴더 매칭 → (AI 리라이팅) → `ThreadsProUploader.post_to_threads()` 호출 → 성공 시 폴더명에 `[완료] ` 접두사 → `delay_minutes` 대기 후 다음 행. 10초 단위로 정지 플래그 검사
- `open_login_session()`: 로그인 창 열기

> ⚠️ **이 클래스는 현재 그대로는 동작하지 않습니다.** `pd`(pandas)를 쓰지만 uploader.py에 `import pandas as pd`가 없어 `load_excel_data`에서 `NameError`가 나고, `open_login_session`은 존재하지 않는 `headless=` 인자를 `run_manual_login`에 넘겨 `TypeError`가 납니다. (문서 06 버그 #1, #2)

## main.py — 구버전 데스크톱 GUI (344줄) ⚠️

customtkinter로 만든 다크 테마 데스크톱 창 (`Threads Auto Uploader`).

- **입력 요소**: 엑셀 파일 선택, 이미지 폴더 선택, 계정 ID, 포스팅 간격(분, 기본 30), Headless 체크박스
- **버튼**: 🔑 스레드 로그인 세션 열기 / 🚀 자동 업로드 시작 / ⏹️ 정지
- **로그 창**: `queue.Queue` + 100ms 폴링(`after`)으로 백그라운드 스레드의 로그를 안전하게 UI에 반영
- 업로드는 `ThreadsUploader.start_upload_process()`를 별도 스레드 + `asyncio.run()`으로 실행
- 세션 저장 위치가 웹 버전과 다름: `threads_session/threads_session_<계정>/` (웹 버전의 `sessions/`와 **호환되지 않아 로그인을 따로 해야 함**)

현재는 위의 uploader.py 버그 때문에 로그인 버튼과 업로드 시작이 모두 에러로 끝납니다.

## static/app.js — 프론트엔드 로직 (944줄)

순수 JavaScript (프레임워크 없음). 주요 부분:

| 영역 | 함수 | 내용 |
|------|------|------|

## run.command / run_gui.command — 실행 스크립트

- `run.command`: 스크립트 위치로 cd → `venv` 활성화 → 3초 뒤 브라우저로 `http://127.0.0.1:5001` 열기(백그라운드) → `python app.py`
- `run_gui.command`: cd → venv 활성화 → `python main.py`

macOS Finder에서 더블클릭으로 실행할 수 있게 `.command` 확장자 사용. venv가 없으면 둘 다 실패.

## 스레드 이미지/ — 샘플 콘텐츠 폴더

구버전 GUI의 "이미지 폴더" 형식 예시이자 실제 사용하던 상품 이미지:

```
스레드 이미지/
├── 1_일본양말/     (1.jpg, 1.jpeg, 2.mp4, 3.jpg, ... — 파일명 숫자 = 첨부 순서)
├── 1_뉴욕쿠키/     (1.jpeg, 2.jpeg)
└── 3_한성기업 만두/ (1_만두.png, 2_만두.png)
```

폴더명 규칙: `번호_상품명`. 번호로 엑셀 행과 매칭되고, 업로드 완료 시 `[완료] 1_일본양말`로 이름이 바뀜. `desktop.ini`가 있는 걸 보면 Windows에서 복사해온 폴더입니다.
