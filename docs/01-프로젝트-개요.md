# 01. 프로젝트 개요

## 이 프로그램은 무엇인가

**Threads Auto Pro**는 Meta의 SNS **Threads(스레드, threads.net)** 에 게시물을 자동으로 올려주는 **개인용 마케팅 자동화 도구**입니다.

전형적인 사용 시나리오:

1. 상품 홍보용 본문(글), 이미지/영상, 해시태그, 게시 시각을 표(또는 엑셀/CSV)로 준비한다.
2. 프로그램에 Threads 계정을 등록하고 브라우저에서 한 번 수동 로그인한다 (세션이 저장됨).
3. "예약 실행"을 누르면, 지정한 시각이 될 때마다 프로그램이 **크롬 브라우저를 자동으로 조종**해서 글을 게시한다.
4. 본문 게시 직후 **첫 댓글(예: 쿠팡 파트너스 구매 링크)** 을 같은 스레드에 자동으로 단다.
5. 원하면 OpenAI(GPT) 또는 Google(Gemini) API로 **본문을 AI가 다시 써주는(리라이팅)** 기능을 쓸 수 있다.

즉, "매일 정해진 시간에 상품 홍보 스레드를 올리고 댓글에 구매 링크를 다는" 반복 작업을 대신해 주는 프로그램입니다.

## 공식 API가 아니라 브라우저 자동화

이 프로그램은 Threads 공식 API를 쓰지 않습니다. 대신 **Playwright**라는 브라우저 자동화 라이브러리로 실제 크롬(Chromium)을 띄워서, 사람이 하는 것과 똑같이:

- threads.net에 접속하고
- "새로운 스레드" 버튼을 클릭하고
- 글을 타이핑하고
- 파일 첨부 버튼으로 이미지를 올리고
- "게시" 버튼을 누릅니다.

봇으로 감지되는 것을 피하려고 다음과 같은 트릭이 들어 있습니다:

- 마우스 커서를 직선이 아닌 **S자 베지에 곡선**으로, 15~25단계로 잘게 나눠 움직임 (`uploader.py`의 `human_move_and_click`)
- 스크롤도 가속/감속을 넣어 사람처럼 굴림 (`human_scroll`)
- 게시 전에 피드를 3~5회 랜덤 스크롤하는 "워밍업" 수행
- `navigator.webdriver` 속성을 숨기고 `--disable-blink-features=AutomationControlled` 옵션으로 자동화 흔적 제거
- 로그인은 사람이 직접 하고, 그때 저장한 쿠키(세션)를 재사용

> ⚠️ 이 방식은 Threads의 화면 구조(HTML)가 바뀌면 언제든 깨질 수 있고, Meta 이용약관상 자동화는 계정 제재 위험이 있습니다. "됐다가 안 됐다가" 하는 근본 원인 중 하나입니다. (문서 06 참고)

## 두 가지 실행 모드

이 저장소에는 사실상 **두 개의 프로그램**이 들어 있습니다. 에이전틱 AI로 개발하면서 구버전(GUI)과 신버전(웹)이 한 저장소에 공존하게 된 것으로 보입니다.

### 1) 웹 버전 — "Threads Auto Pro" (현재 메인) ✅

| 항목 | 내용 |
|------|------|
| 실행 | `run.command` 또는 `python app.py` → 브라우저에서 `http://127.0.0.1:5001` |
| 구성 | `app.py`(Flask 서버) + `templates/index.html` + `static/app.js`, `static/style.css` |
| 자동화 엔진 | `uploader.py`의 **`ThreadsProUploader`** 클래스 |
| 기능 | 다중 계정 관리, 시간(HH:MM) 예약 스케줄러, CSV/엑셀 불러오기, AI 리라이팅, 실시간 로그(SSE), 대시보드 |
| 데이터 저장 | `config.json`(설정·계정), `queue.json`(예약 대기열), `sessions/`(로그인 세션) |

### 2) 데스크톱 GUI 버전 (구버전) ⚠️ 현재 고장 상태

| 항목 | 내용 |
|------|------|
| 실행 | `run_gui.command` 또는 `python main.py` |
| 구성 | `main.py`(customtkinter 데스크톱 창) |
| 자동화 엔진 | `uploader.py`의 **`ThreadsUploader`** 클래스 (내부에서 `ThreadsProUploader` 재사용) |
| 방식 | 엑셀의 폴더 번호와 로컬 이미지 폴더(예: `1_일본양말`)를 매칭해서 순차 업로드. 완료된 폴더는 `[완료]` 접두사를 붙여 이름 변경 |
| 상태 | `uploader.py`에 `import pandas` 누락, 로그인 함수 인자 오류 등 **그대로는 실행 자체가 불가능한 버그**가 있음 (문서 06 참고) |

## 기술 스택

| 분류 | 사용 기술 |
|------|-----------|
| 언어 | Python 3 (백엔드), Vanilla JavaScript (프론트엔드) |
| 웹 서버 | Flask (로컬 전용, 127.0.0.1:5001) |
| 브라우저 자동화 | Playwright (async API, Chromium) |
| 데스크톱 GUI | customtkinter (구버전) |
| 데이터 처리 | pandas + openpyxl (엑셀/CSV 파싱) |
| AI 리라이팅 | openai SDK (gpt-4o-mini), google-generativeai SDK (gemini-2.5-flash 등) |
| 실시간 로그 | Server-Sent Events (SSE) |
| 저장소 | 파일 기반 (JSON) — DB 없음 |

## 저장소 구조 한눈에 보기

```
threads-automation/
├── app.py                 # ✅ 웹 버전 Flask 서버 + 예약 스케줄러 (메인)
├── uploader.py            # ✅ 핵심 자동화 엔진 (Playwright 조작, AI 리라이팅)
├── main.py                # ⚠️ 구버전 데스크톱 GUI (현재 버그로 고장)
├── templates/index.html   # 웹 화면 HTML (탭 3개: 설정/데이터입력/대시보드)
├── static/app.js          # 웹 프론트엔드 로직
├── static/style.css       # 웹 디자인 (라이트 테마)
├── run.command            # 웹 버전 실행 스크립트 (macOS 더블클릭용)
├── run_gui.command        # GUI 버전 실행 스크립트
├── test_upload.py         # 업로드 기능 수동 테스트 스크립트 (개발용)
├── dump_modal.py          # Threads 화면의 버튼 HTML을 출력하는 디버깅 스크립트 (개발용)
├── requirements.txt       # 의존성 목록 (⚠️ 일부 누락 있음 — 문서 02 참고)
├── .gitignore
├── 스레드 이미지/          # 샘플 상품 이미지 (일본양말, 뉴욕쿠키, 한성기업 만두)
└── (실행하면 생김) config.json, queue.json, sessions/
```

## 이 프로그램이 하지 않는 것

- 서버에 배포해서 쓰는 서비스가 아님 — **본인 컴퓨터에서만** 도는 로컬 프로그램 (인증/보안 없음)
- Threads 공식 API 사용 안 함
- 데이터베이스 없음 — 모든 상태가 JSON 파일
- 컴퓨터가 꺼져 있거나 프로그램이 꺼져 있으면 예약이 실행되지 않음 (지나간 예약은 소급 실행되지 않음)
